# Wanted AI Championship 2026 Submission Draft

## 제출 프로젝트

OpsMate Local

## 한 줄 소개

자연어 구매 요청을 AI가 정책 근거가 연결된 구조화 초안으로 만들고, 서버 검증과 사람 승인을 통과한 요청만 실제 발주 단계로 진행시키는 안전한 AI 업무 서비스입니다.

## 해결하려는 문제

구매 요청과 같은 업무에서는 사용자가 자유롭게 작성한 요청을 정해진 정책과 형식에 맞게 정리하는 데 시간이 들고, AI가 생성한 결과를 그대로 업무 처리에 연결하면 잘못된 정책 적용이나 권한 없는 상태 변경으로 이어질 수 있습니다.

OpsMate Local은 AI를 의사결정자가 아니라 초안 작성 도구로 제한합니다. AI가 구매 요청을 구조화하고 관련 정책 근거를 제안하면, Spring 서버가 권한, 상태, 정책 식별자와 데이터 형식을 다시 검증합니다. 이후 사람의 승인까지 완료된 요청만 발주할 수 있습니다.

## 주요 사용자 흐름

1. REQUESTER가 자연어로 구매 요청을 입력합니다.
2. AI가 정책 근거를 바탕으로 구조화된 구매 요청 초안을 생성합니다.
3. 서버가 AI 출력의 구조와 업무 규칙을 다시 검증합니다.
4. REQUESTER가 검증된 초안을 승인 대기 상태로 제출합니다.
5. APPROVER가 승인 또는 반려합니다.
6. BUYER는 승인된 요청만 발주할 수 있습니다.
7. AUDITOR는 요청, 승인, 발주 이력을 확인합니다.

## AI 활용 방식

### 서비스 런타임 AI

- 모델: Gemma 3 12B
- 실행: Ollama
- 역할: 자연어 구매 요청을 서버가 제공한 합성 정책 근거에 따라 구조화된 구매 요청 초안으로 변환
- 제한: AI는 승인, 반려, 발주를 직접 수행하지 않으며 DB나 임의 URL에 접근하지 않습니다.
- 검증: 실제 모델 기반 합성 업무 시나리오 9건 E2E를 수행했습니다.

### AI 안전 경계

AI 출력은 신뢰된 업무 데이터로 취급하지 않습니다.

```text
사용자 자연어 요청
-> 서버가 정책 근거 제공
-> AI가 구조화 초안 제안
-> 서버가 출력/정책/권한/상태 재검증
-> 사람 승인
-> 승인된 요청만 발주
```

모델 응답이 비정상 형식이거나 너무 크거나 시간 초과가 발생하면 저장과 후속 업무 처리를 진행하지 않는 fail-closed 방식으로 구현했습니다.

## 구현 및 검증 상태

다음 범위를 실제 구현 및 bounded E2E로 확인했습니다.

- 자연어 요청 -> 실제 모델 기반 초안 생성
- 요청 제출 -> 승인/반려 -> 승인된 요청의 발주 -> 감사 기록
- 역할별 권한 통제
- 서로 다른 브라우저 세션 간 workspace 격리
- 모델 출력 재검증 및 실패 시 fail-closed
- 공개 HTTPS ingress
- PostgreSQL 및 AI model endpoint의 직접 외부 노출 차단
- 동일 검증 release의 close/reopen
- 비상 종료 후 복구
- 공개 경로 rate limit

2026-08-29 공개 인터넷 E2E 검증 후 애플리케이션 workload는 안전을 위해 CLOSED 상태로 유지했습니다. 대회 제출 시에는 검증된 release를 다시 열고 심사 기간 동안 서비스 접근 가능 상태를 유지해야 합니다.

## 사용자 가치

- 자연어 요청 작성 부담을 줄입니다.
- AI 결과를 업무 트랜잭션에 그대로 연결하지 않고 서버 검증과 사람 승인을 거치게 합니다.
- AI 활용과 기존 업무 권한/감사 체계를 함께 유지할 수 있는 구조를 보여줍니다.
- 구매 외에도 승인 기반 사내 업무 요청으로 확장할 수 있습니다.

## 확장 가능성

동일한 패턴을 다음과 같은 승인형 업무에 적용할 수 있습니다.

- 비용/지출 요청
- 계정 또는 권한 요청
- 변경 작업 요청
- 내부 운영 작업
- 정책 기반 업무 초안 생성

핵심은 도메인별 AI 초안 생성 로직과 정책 근거를 교체하면서도 권한, 상태 전이, 사람 승인, 감사 기록이라는 서버 통제 구조를 재사용하는 것입니다.

## 공개 및 권리 경계

- 개인이 독립적으로 만든 공개 포트폴리오 프로젝트입니다.
- 회사 코드, 고객 데이터, 회사 내부 URL, 자격증명 또는 실제 업무 규칙을 포함하지 않습니다.
- 서비스 데이터와 정책은 모두 합성 예시입니다.
- 실제 운영 서비스 또는 24x7 SLA를 주장하지 않습니다.
- 대회 심사 기간 동안 공개 데모에 사용하는 데이터도 합성 데이터만 사용합니다.
