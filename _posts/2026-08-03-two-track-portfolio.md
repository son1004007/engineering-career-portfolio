한 서비스에 모든 기술을 넣으면 화려해 보일 수는 있지만, 어떤 역량이 실제 업무에서 나온 것인지 구분하기 어려워집니다. 그래서 이 포트폴리오는 두 트랙을 분리했습니다.

## 트랙 A — 신규 대표 프로젝트

`OpsMate Local`은 AI Agent 응용 역량을 보여주기 위한 신규 프로젝트입니다. 구매 요청부터 승인·발주까지 수직 기능과 19개 자동화 테스트가 존재해 현재 상태는 `implemented`, `tested-component`입니다. 실제 오픈웨이트 모델 서버 E2E와 운영 배포까지 검증됐다는 뜻은 아닙니다.

첫 범위는 다음 구매 흐름으로 제한합니다.

```text
자연어 구매 요청
→ 정책 근거 검색
→ 구매요청 초안
→ 사람 승인 또는 반려
→ 승인된 요청만 발주 생성
→ 감사 이벤트 기록
```

핵심은 LLM이 업무 DB를 직접 조작하는 데 있지 않습니다. Spring 서비스가 RBAC, 객체 단위 조회 권한, 상태 전이, 중복 방지와 업무 규칙을 최종 검증하고, 모델 오류에서는 쓰기 경로를 `fail-closed`로 중단합니다. 실제 모델 서버가 없을 때 외부 유료 API로 자동 우회하지 않습니다.

## 트랙 B — 기존 업무 사례

기존 업무 사례는 Java/Spring, SQL, 인증, 배포와 운영의 실무 깊이를 보여줍니다. 비공개 원본에서 코드와 본인 귀속을 확인한 사례도 원본 소스나 내부 식별자를 공개하지 않습니다.

공개 게시물에 코드가 필요하면 일반화한 도메인과 합성 데이터로 독립 구현하고, 정상·실패·경계 조건 테스트가 최근 성공한 뒤에만 `sample-verified`로 올립니다.

## 두 트랙을 연결하는 문장

> 기존 실무 사례로 엔터프라이즈 백엔드의 깊이를 증명하고, OpsMate Local로 그 기반 위에 AI Agent를 안전하게 통합하는 현재 역량을 증명한다.

이 구조는 ML 모델 연구자를 지향한다는 뜻이 아닙니다. Java/Spring 백엔드와 플랫폼 역량을 중심으로, 오픈웨이트 LLM을 업무 트랜잭션에 통합할 수 있는 엔지니어가 목표입니다.
