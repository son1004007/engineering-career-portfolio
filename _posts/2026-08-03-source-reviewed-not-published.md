실무 포트폴리오에서는 무엇을 만들었다는 설명만큼, 어디까지 확인됐는지를 보여주는 일이 중요합니다. 이 저장소는 사례의 상태를 다음과 같이 분리합니다.

| 상태 | 확인된 것 | 아직 확인되지 않은 것 |
|---|---|---|
| `source-reviewed` | 권한 있는 환경에서 비공개 원본 코드와 본인 귀속을 확인 | 공개 재현 코드와 최근 테스트 성공 |
| `sample-verified` | 독립 재현 샘플과 최근 테스트 성공 기록 존재 | 실제 회사 시스템 전체 성과 |
| `published` | 게시물, 공개 코드, 테스트와 공개 안전성 검토가 서로 일치 | 비공개 원본의 공개 권한 |

## 현재 확인된 Java/Spring 사례

SSO와 DB 계정 인증을 Spring Security 흐름으로 통합한 사례는 회사 코드와 독립된 샘플을 만들고 24개 테스트를 최근 성공해 `sample-verified`로 올렸습니다.

아직 `source-reviewed` 상태에 머무는 주제는 다음과 같습니다.

- MyBatis·Oracle 업무 조회의 정합성과 성능 개선
- WAR 기반 Spring MVC/JSP 서비스의 환경 독립 배포
- 여러 계층에 분산된 기준값과 사용자 식별 규칙 정합화
- Java/Spring 통계 품질 분석 화면에서 CSV·Excel 데이터와 Xbar-R 시각화 연결

이 네 사례는 공개 샘플이 완성됐다는 의미가 아닙니다. 각각 합성 데이터와 일반화한 도메인으로 다시 구현하고 테스트해야 합니다.

## 왜 원본 코드를 보여주지 않는가

회사 소유 코드는 포트폴리오의 증거 확인에만 사용합니다. 저장소명, 고객명, 내부 URL, 커밋 메시지, 파일 경로, SQL과 설정은 게시하지 않습니다. 공개 샘플은 원본을 복사하지 않고 요구사항과 테스트부터 새로 작성합니다.

따라서 채용 담당자는 상태 배지를 통해 다음을 빠르게 구분할 수 있습니다.

1. 실제 원본과 개인 기여를 확인했는가
2. 공개 가능한 코드가 별도로 있는가
3. 그 코드의 최근 테스트 성공이 기록됐는가
4. 설명이 확인된 범위를 넘어가지 않는가
