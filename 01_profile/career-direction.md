# Career Direction

## 현재 방향

손기석은 **특정 언어나 프레임워크에 한정되지 않고, 업무 문제를 시스템으로 구조화해 구현·검증·운영까지 연결하는 소프트웨어/백엔드/플랫폼 엔지니어**를 지향합니다.

Java/Spring, Python/FastAPI, SQL, Docker, LLM은 그 역할을 수행하기 위한 실제 사용 기술입니다. 기술 이름 자체보다 다음 역량을 커리어의 중심으로 둡니다.

- 문제와 제약을 구조화하는 능력
- 서비스와 데이터 흐름을 설계하는 능력
- AI를 개발 과정과 서비스 기능에 활용하는 능력
- 권한, 실패, 감사와 같은 통제 경계를 설계하는 능력
- 테스트와 실제 실행 결과로 품질을 검증하는 능력
- 배포, 운영, 복구와 재현성을 고려하는 능력

---

## 왜 이 방향을 선택했는가

### 1. 개발 환경이 바뀌어도 남는 역량을 중심에 둔다

AI가 코드 작성과 기술 탐색을 빠르게 도와주는 환경에서는 특정 framework API를 많이 외우는 것만으로 차별화하기 어렵습니다.

대신 다음 능력은 계속 중요합니다.

```text
무엇을 만들어야 하는지 정의
어디까지 시스템이 책임져야 하는지 결정
잘못된 결과를 어떻게 막을지 설계
여러 구성요소를 연결
실제 동작을 검증
운영 가능한 상태로 마무리
```

언어와 framework는 바뀔 수 있지만 이 문제 해결 과정은 남는다고 봅니다.

### 2. 백엔드는 중요한 기반이지만 정체성 전체는 아니다

Java/Spring 기반 서비스 개발, DB 연계, API 구현과 운영 경험은 현재 강한 기반입니다.

하지만 공개 포트폴리오와 장기 커리어는 `Java 개발자`라는 한 문장으로 제한하지 않습니다.

백엔드는 데이터, AI, 보안, 운영을 실제 서비스로 연결하는 중심 역할로 사용합니다.

### 3. AI는 새로운 언어가 아니라 개발 방식과 시스템 기능의 변화다

AI는 두 가지로 사용합니다.

```text
개발 과정:
조사, 계획, 구현, 테스트, 리뷰를 가속

서비스 기능:
자연어 이해, 초안 생성, 검색과 데이터 질의 지원
```

중요한 것은 AI를 호출하는 것보다, AI가 잘못된 결과를 만들거나 unavailable한 경우에도 시스템의 핵심 규칙과 데이터가 보호되게 만드는 것입니다.

### 4. 데이터와 운영은 기술 변화에도 오래 남는 기반이다

실제 업무 시스템은 결국 데이터와 운영환경 위에서 동작합니다.

따라서 다음 역량을 계속 확장합니다.

- 데이터 정합성과 SQL
- API와 시스템 간 contract
- 배포와 실행환경
- 로그와 장애 분석
- 복구와 재현 가능성

### 5. 보안 경험은 별도 직무가 아니라 설계 관점으로 활용한다

정보보안 경험을 개발과 분리된 과거 경력으로 두지 않습니다.

권한, 최소 권한, 감사, 변경 추적, 실패 시 안전한 처리 같은 원칙을 시스템 설계에 함께 적용하는 차별점으로 사용합니다.

## 커리어 방향 4축

### 1. Software / Backend Engineering

- 업무 문제를 API, DB, 상태와 트랜잭션 구조로 구현
- 서비스 경계와 실패 조건 설계
- Java/Spring 또는 Python/FastAPI 등 적절한 기술 선택
- 테스트와 운영 결과까지 책임지는 개발

### 2. Data / AI Service Integration

- 데이터 분석 결과의 서비스화
- Text2SQL/NL2SQL, RAG, LLM 기반 기능
- AI 결과 검증과 evaluation
- API, DB, 검색, 문서와 모델의 연결

### 3. Platform / Operations

- Linux, Docker, application server와 network boundary
- CI/CD, health verification, rollback
- 재현 가능한 환경과 release
- 장애 분석과 운영 증거

### 4. Security / Governance by Design

- 인증·인가
- 접근통제
- 감사 이벤트
- 최소 권한
- fail-closed
- artifact/provenance와 변경 추적

## 목표 직무

직무명보다 실제 업무 내용을 우선하지만, 시장에서 다음 직무군과 연결될 수 있습니다.

### 주요 후보

- Backend Engineer
- Backend Platform Engineer
- Platform Engineer
- Data Platform Backend Engineer
- AI Service / AI Platform Backend Engineer
- Software Engineer for internal/business platforms
- DevSecOps Engineer
- Application Security Engineer
- 보안 자동화·권한관리·감사 시스템 개발

### 장기 확장

- 기술 아키텍처와 품질 검토
- IT 내부통제
- IT Risk / IT Audit
- 정보시스템 감리

장기 확장은 개발과 운영을 직접 수행한 기술적 근거를 기반으로 접근합니다.

## 역할 선택 기준

다음 질문으로 역할을 평가합니다.

1. 실제 문제와 시스템 구조를 이해하고 설계할 수 있는가
2. 코드뿐 아니라 데이터, 테스트, 배포와 운영 결과까지 연결할 수 있는가
3. AI를 단순 유행 기능이 아니라 업무 흐름 안에서 안전하게 활용할 수 있는가
4. 본인의 기술적 판단과 산출물이 명확하게 남는가
5. 권한, 실패, 변경과 감사 관점을 설계에 반영할 수 있는가
6. 특정 vendor나 한 framework에만 종속되지 않고 역량을 확장할 수 있는가

## 앞으로 보여주고 싶은 엔지니어 이미지

- 특정 언어를 많이 아는 사람보다 문제를 정확히 정의하는 엔지니어
- AI가 만든 코드와 결과도 다시 검증할 수 있는 엔지니어
- 백엔드, 데이터, AI, 보안과 운영의 경계를 연결할 수 있는 엔지니어
- 만들었다는 설명보다 테스트와 실행 evidence를 남기는 엔지니어
- 다른 개발자나 AI가 이어받을 수 있는 구조와 문서를 만드는 엔지니어
- 기술이 바뀌어도 문제 해결 방식이 유지되는 엔지니어

---

## 한 줄 요약

손기석은 **문제를 시스템으로 구조화하고 AI와 적절한 기술을 활용해 구현하며, 검증과 운영까지 끝낼 수 있는 소프트웨어/백엔드/플랫폼 엔지니어**를 지향합니다.
