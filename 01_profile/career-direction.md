# Career Direction

## 현재 방향

손기석의 공개 역할은 **Backend Engineer - AI Integration & Reliable Systems**로 정리합니다.

특정 언어나 프레임워크에 한정하지 않되, 채용 담당자가 첫 화면에서 역할을 즉시 이해할 수 있도록 Backend Engineer를 중심에 둡니다. Java/Spring, Python/FastAPI, SQL, Docker와 LLM은 이 역할을 수행하기 위한 실제 사용 기술입니다.

커리어의 중심 역량은 다음과 같습니다.

- 업무 요구사항을 백엔드 시스템 구조로 바꾸는 능력
- 서비스와 데이터 흐름을 설계하는 능력
- AI를 실제 업무 기능에 안전하게 연결하는 능력
- 권한, 실패와 감사 경계를 설계하는 능력
- 테스트와 실제 실행 결과로 품질을 검증하는 능력
- 배포, 운영과 복구를 고려하는 능력

---

## 왜 이 방향을 선택했는가

### 1. 시장에서 역할은 명확하게, 구현 기술은 유연하게 가져갑니다

특정 framework API를 많이 아는 것만으로는 장기 차별화가 어렵지만, 역할 자체가 모호하면 채용 시장에서 분류되기 어렵습니다.

따라서 다음 두 원칙을 같이 적용합니다.

```text
역할:
Backend Engineer로 명확하게 분류

도구:
Java/Spring, Python/FastAPI, SQL, Docker, LLM을 문제에 맞게 선택
```

### 2. 백엔드는 데이터, AI, 보안과 운영을 연결하는 중심 역할입니다

Java/Spring 기반 서비스 개발, DB 연계, API 구현과 운영 경험은 현재 가장 강한 기반입니다.

하지만 `Java 개발자` 한 문장으로 역할을 제한하지는 않습니다. 백엔드 시스템 안에서 데이터, AI 기능, 권한과 운영 경계를 연결하는 것이 핵심입니다.

### 3. AI는 별도 유행 직무보다 백엔드 기능으로 다룹니다

AI는 두 가지로 사용합니다.

```text
서비스 기능:
자연어 이해, 초안 생성, 검색과 데이터 질의 지원

개발 과정:
조사, 계획, 구현과 리뷰를 가속
```

중요한 것은 AI를 호출하는 것보다, 모델이 잘못된 결과를 만들거나 사용할 수 없는 경우에도 핵심 업무 규칙과 데이터가 보호되게 만드는 것입니다.

### 4. 데이터와 운영은 신뢰할 수 있는 백엔드를 만드는 기반입니다

실제 업무 시스템은 결국 데이터와 운영환경 위에서 동작합니다.

따라서 다음 역량을 계속 확장합니다.

- 데이터 정합성과 SQL
- API와 시스템 간 contract
- 배포와 실행환경
- 로그와 장애 분석
- 복구와 재현 가능성

### 5. 보안 경험은 별도 과거 경력이 아니라 설계 관점으로 활용합니다

권한, 최소 권한, 감사, 변경 추적과 안전한 실패 처리를 백엔드 시스템 설계에 함께 적용합니다.

## 커리어 방향 4축

### 1. Backend Engineering

- 업무 문제를 API, DB, 상태와 트랜잭션 구조로 구현
- 서비스 경계와 실패 조건 설계
- Java/Spring 또는 Python/FastAPI 등 적절한 기술 선택
- 테스트와 운영 결과까지 연결

### 2. Data / AI Service Integration

- 데이터 분석 결과의 서비스화
- Text2SQL/NL2SQL, RAG, LLM 기반 기능
- AI 결과 검증과 evaluation
- API, DB, 검색, 문서와 모델의 연결

### 3. Reliability / Operations

- Linux, Docker, application server와 network boundary
- CI/CD, health verification, rollback
- 재현 가능한 환경과 release
- 장애 분석과 운영 근거

### 4. Security / Governance by Design

- 인증과 인가
- 접근통제
- 감사 이벤트
- 최소 권한
- fail-closed
- 변경과 결과 추적

## 목표 직무

시장에서는 Backend Engineer를 기본 분류로 사용합니다. 실제 공고의 업무 범위에 따라 다음 직무군도 검토할 수 있습니다.

### 주요 후보

- Backend Engineer
- Internal Platform Backend Engineer
- Data Platform Backend Engineer
- AI Service Backend Engineer
- AI Platform Backend Engineer
- Software Engineer for internal/business systems
- Security Automation Backend Engineer
- Application Security Engineer with development ownership

`Platform Engineer` 단독 title은 현재 공개 포트폴리오의 상위 정체성으로 사용하지 않습니다. IaC, Kubernetes, 내부 개발자 플랫폼, 중앙 관측성, 멀티환경 운영과 같은 직접 증거가 충분히 쌓인 뒤 다시 검토합니다.

### 장기 확장

- 기술 아키텍처와 품질 검토
- IT 내부통제
- IT Risk / IT Audit
- 정보시스템 감리

장기 확장은 개발과 운영을 직접 수행한 기술적 근거를 기반으로 접근합니다.

## 역할 선택 기준

다음 질문으로 역할을 평가합니다.

1. 실제 문제와 시스템 구조를 이해하고 설계할 수 있는가
2. 코드뿐 아니라 데이터, 테스트, 배포와 운영 결과까지 연결할 수 있는가
3. AI를 단순 유행 기능이 아니라 업무 흐름 안에서 안전하게 활용할 수 있는가
4. 본인의 기술적 판단과 산출물이 명확하게 남는가
5. 권한, 실패, 변경과 감사 관점을 설계에 반영할 수 있는가
6. 특정 vendor나 한 framework에만 종속되지 않고 역량을 확장할 수 있는가

## 앞으로 보여주고 싶은 엔지니어 이미지

- 역할은 Backend Engineer로 명확하지만 언어 하나에 갇히지 않는 엔지니어
- AI 결과를 그대로 믿지 않고 서버 규칙과 테스트로 검증하는 엔지니어
- 백엔드, 데이터, AI, 보안과 운영 경계를 연결할 수 있는 엔지니어
- 만들었다는 설명보다 실제 실패 차단과 실행 결과를 남기는 엔지니어
- 다른 개발자나 AI가 이어받을 수 있는 구조와 문서를 만드는 엔지니어
